# Защита русского текста от mojibake

## Что такое mojibake

Порча кириллицы из-за неправильной кодировки. Примеры патологических паттернов:

- `РњСЏСЃРѕ` вместо `Мясо` (CP1251 → UTF-8 → снова CP1251).
- `РџСЂРѕРµРєС‚` вместо `Проект`.
- `вЂ”`, `в„–`, `Р°`, `С»` — явные следы перекодировки.

Всё это блокирующие баги. CI падает на `guard:mojibake`.

## Жёсткие правила

- Все текстовые файлы с русским текстом — **только UTF-8 без BOM**.
- В Windows PowerShell читать через `Get-Content -Encoding UTF8 <file>`, иначе консоль может показать кракозябры, которых на диске нет.
- Не копировать русский текст из источников с mojibake.
- Не менять `charset`, `lang="ru"`, meta-теги без проверки результата.
- Не трогать `word-break: keep-all; hyphens: none` — это защита переноса кириллицы.
- Не добавлять `hyphens: auto` на русские блоки.
- Не менять `Accept-Charset`, `Content-Type` без явной задачи.

## Проверка до build

```
npm --prefix frontend run guard:mojibake
```

Гарантирует, что `frontend/src`, `index.html`, `manifest.webmanifest`, `robots.txt`, `sitemap.xml` чисты.

## Проверка после правки

- Открыть изменённый файл с явным UTF-8 и убедиться, что кириллица читается.
- Если правил в PowerShell, использовать `Out-File -Encoding utf8NoBOM` или редактор с явной UTF-8 настройкой.

## Запреты

- Массовая перекодировка файлов без явной задачи.
- «Починить mojibake по всему проекту» — только если владелец это явно попросил.
- Вставлять русские строки из внешних источников без визуальной проверки.

## Если подозрение на mojibake

1. Прочитать файл с `skipPruning: true` через `read_file`, проверить визуально.
2. Сравнить байты через `hexdump` (Linux) или `Format-Hex` (PowerShell).
3. Сначала выяснить источник (последний коммит, импорт, правка), потом чинить.
