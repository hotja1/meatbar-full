# Design critique — 5-dimensional self-check + anti-AI-slop

Основано на [huashu-design](https://github.com/alchaincyf/huashu-design) и [open-design](https://github.com/nexu-io/open-design). Перед тем как сдать любую визуальную правку, ИИ прогоняет её по 5 осям и проверяет на AI-slop. Если хотя бы одна ось < 3/5 — это регрессия, возвращаемся и правим.

## 5 осей самокритики (скоринг 1–5)

### 1. Philosophy — понимание бренда и сценария

- Передаёт ли работа характер «Мясо Бара» (тёплый ресторанный премиум, огонь, мясо, атмосфера)?
- Ощущается ли Нижневартовск / русский ресторан / живой зал?
- Нет ли generic-SaaS-ощущения (холодные градиенты, синий, дженерик-геометрия)?

Плохо 1/5: «дашборд для стартапа». Отлично 5/5: «чувствуешь запах угля, Monocle-меню в руке».

### 2. Hierarchy — визуальная иерархия

- Есть ли один главный фокус на экране?
- Читабельно с первого взгляда без усилий?
- Отступы работают как пауза, а не как пустота?
- H1 действительно H1, H2 действительно H2?

Плохо 1/5: «три CTA одинакового размера». Отлично 5/5: «понял за 1.5 секунды, куда нажать».

### 3. Detail — качество исполнения

- Границы/радиусы/тени согласованы?
- Цифры/текст выровнены по сетке?
- Нет «пограничных» пикселей (полтора пикселя border, 11.3px padding)?
- Микро-интеракции ощущаются, не мешая?

Плохо 1/5: «кнопка съехала на 2 пикселя». Отлично 5/5: «пиксель-перфект, даже на 4K».

### 4. Function — работает ли для пользователя

- Можно ли добраться до главного (бронь, заказ) без когнитивной нагрузки?
- Кликабельное — реально кликабельное (≥ 44×44 px на мобильном)?
- Формы защищают от ошибок (валидация, маска телефона, состояния loading/error)?
- Есть ли fallback, если API упал?

Плохо 1/5: «красиво, но я не понимаю как забронировать». Отлично 5/5: «забронировал за 20 секунд, ошибок ноль».

### 5. Restraint — когда остановился

- Нет «AI-мусора» (см. blacklist ниже)?
- Нет лишних эффектов «потому что могу»?
- Типографика > эффекты? Свет > цвет? Паузы > движение?
- Визуал старше на полгода, чем сегодня?

Плохо 1/5: «кажется что делал кто-то, кто увидел AI впервые». Отлично 5/5: «выглядит как COMA Berlin или Ad Astra Helsinki».

## Anti-AI-slop blacklist

Никогда не отдаём работу, если в ней есть:

- Фиолетовые градиенты (purple → pink → blue) — маркер дженерик-AI-дизайна 2023–2025.
- Неоновые зелёные/синие акценты на тёмном фоне.
- Карточка со скругленными углами + левой accent-полоской (overused SaaS pattern).
- Generic emoji-иконки в UI (🚀 🎉 ✨ 💡 🌟 и т.п.) — только SVG-line icons, 24 px, `currentColor`.
- Inter как **display**-гарнитура для крупных заголовков (OK для body, плохо для hero).
- Inter + Poppins + DM Sans + Space Grotesk — «modern SaaS stack». У нас сериф display.
- Придуманные числа («10× быстрее», «97% пользователей довольны») без источника.
- Placeholder-типографика lorem ipsum в финальной сдаче.
- Hand-drawn SVG-человечки (Notion-маскоты).
- Пастельные blob-фоны.
- Скруглённый квадрат-логотип с градиентом внутри (generic favicon-pattern).
- Чистый `#000` / `#fff` — у нас `--coal` и `--cream`.
- Одинаковые CTA трёх штук подряд без иерархии.
- Hover-эффект «повернулся на 5° и подпрыгнул» — у нас sober premium.

## Honest placeholders вместо fake stats

Если нет реальной цифры — **не придумываем**. Пишем:

- `—` (длинное тире) для «пока не измеряли»
- «Готовится», «В работе», «Уточняется»
- Labeled grey block вместо фейкового графика

Лучше честный пустой блок, чем «увеличили конверсию на 37%» без источника.

## Brand-asset protocol (когда дают новый референс)

Если владелец скидывает фото, скриншот, URL с референсом — **не угадывать цвета по памяти**. Порядок:

1. **Locate** — найти исходный файл/скриншот.
2. **Extract** — выделить реальные hex-значения (eyedropper, grep по CSS, Canvas getImageData).
3. **Codify** — записать в `brand-spec.md` или комментарии как `// ember-from-ref: #d81420`.
4. **Vocalise** — проговорить: «беру ember с угольков с фото 3, brass с винной этикетки».
5. **Apply** — только после этого код.

Это защита от того, что ИИ на память ставит «что-то похожее» и получается mojibake-цвет.

## Процесс: перед тем как сдать результат

- [ ] Прогнал 5 осей, нигде нет ниже 3/5.
- [ ] Проверил anti-AI-slop blacklist — ничего из него нет.
- [ ] Типографика читается, иерархия ясна.
- [ ] Все цвета из `:root` переменных.
- [ ] Все картинки в AVIF/WebP с `-sm` вариантом.
- [ ] Все анимации имеют `prefers-reduced-motion` ветку.
- [ ] Проверил на `data-perf='low'` — не разваливается.
- [ ] Нет придуманных числовых утверждений.
- [ ] Нет generic-emoji в UI.

Если чек-лист не пройден — переделываю. Не сдаю владельцу «на доработку» — сдаю готовое.

## Пример self-report (формат для отчёта)

```
Self-critique:
- Philosophy: 4/5 — передаёт ресторанную атмосферу, но мог бы сильнее.
- Hierarchy: 5/5 — один фокус, ясно куда смотреть.
- Detail: 4/5 — 1 пиксель съехал в hover-состоянии, починил.
- Function: 5/5 — бронь доступна в 2 клика, fallback работает.
- Restraint: 5/5 — нет лишних эффектов.
Итого: 4.6/5 — готово к показу.
```

Если ниже 4/5 в среднем — дорабатываю до показа.
