# Git и секреты

## Никогда

- Не пушить в `main` / `master` напрямую.
- Не делать force-push (`git push --force`, `--force-with-lease`) без явного согласия.
- Не использовать `git reset --hard`, `git clean -f`, `git branch -D` без явного согласия.
- Не менять `git config` без запроса.
- Не `--amend` чужие коммиты. Только свои неотправленные, и только если задача требует.
- Не коммитить `.env`, `node_modules/`, `dist/`, `build/`, `.DS_Store`, `*.sqlite`, `*.sqlite-shm`, `*.sqlite-wal`.
- Не коммитить реальные токены, ключи, API-секреты. Только `.env.example` с пустыми значениями.
- Не использовать интерактивные флаги (`-i`) — не работают в автоматическом режиме.
- Не пропускать pre-commit hooks (`--no-verify`) без явного согласия.

## Коммиты

- Один коммит — одна логическая задача.
- Сообщение: что сделано и зачем, не «fix stuff».
- Формат: глагол в настоящем времени, 50–72 символа на первую строку.
- Тело коммита — опционально, но при больших изменениях полезно.
- Перед коммитом: `git status` должен быть предсказуемым (не тянуть лишнего).

## Ветки и PR

- Фичевые ветки: `feat/<короткое-описание>`.
- Бэгфиксы: `fix/<короткое-описание>`.
- `git push -u origin <branch>` при первом пуше.
- PR создавать через `gh pr create`, заголовок ≤ 70 символов, подробное описание в body.
- Описание PR: что, зачем, что тестировал, какие риски.

## Секреты

- Все секреты только через `.env` + менеджер секретов на VPS.
- Templates — `backend/.env.example` и `frontend/.env.example` (уже есть).
- JWT_SECRET менять при утечке.
- ADMIN_BOOTSTRAP_PASSWORD менять после первого логина в админку.
- YooKassa / SMS / Telegram / VK токены — никогда не логировать, никогда не показывать в UI.

## Чувствительные файлы — флажок

Перед `git add` проверять, нет ли в diff:

- Пароли.
- Приватных ключей (`-----BEGIN ... PRIVATE KEY-----`).
- AWS/YC ключей (`AKIA...`, `yca...`).
- Telegram bot tokens (`\d+:[A-Za-z0-9_-]{35}`).
- VK access tokens.

Если нашёл — не коммитить, предупредить владельца.

## SSH и VPS

- Подключаться к VPS только по ключу, не по паролю.
- Перед `scp`/`rsync` — проверять `--dry-run`.
- `rm -rf` на сервере — только если владелец явно попросил, с пояснением что удаляется.
- Бэкап SQLite перед любой миграцией схемы.
